## Recommended execution order

1. **001** first — establishes the global reduced-motion gate independently
   of everything else; zero risk of conflicting with other plans.
2. **002** next — removes ambient background from the dashboard/data views,
   the single highest-leverage cohesion fix. Independent of 001.
3. **003** — fixes the Sheet's competing motion systems and adds
   `--ease-drawer` to `styles.css`. Independent, but do before 004 since
   both touch the same `:root` token block (order avoids a merge conflict
   if applied by hand; if using git, either order is safe since both are
   pure additions).
4. **004** — adds `--ease-out` and applies it to five components. If 003
   already ran and added `--ease-drawer` to `:root`, add `--ease-out` as a
   sibling line, don't touch `--ease-drawer`.
5. **005** — depends on 004 only in that it touches the same
   `AlertDialogContent` class string; if both are executed, apply 004
   first (adds `ease-[var(--ease-out)]`), then 005 (splits `duration-200`
   into open/closed variants) — 005's plan text already accounts for this
   ordering. If only 005 is selected without 004, it works standalone.
6. **006**, **007**, **008** — fully independent of everything else and of
   each other; any order, any subset.

## Dependencies

- **004 → 005**: both edit `AlertDialogContent`'s class string in
  `alert-dialog.tsx`. Apply 004 before 005 if both are in scope (see
  above); 005's own plan text handles the case where 004 hasn't run.
- **003 & 004**: both add a new custom property to the same `:root` block
  in `src/styles.css` (`--ease-drawer` and `--ease-out` respectively).
  Purely additive — no conflict regardless of order.
- No other cross-plan dependencies. 001, 002, 006, 007, 008 touch entirely
  separate files from each other and from 003/004/005.

## Not planned (from the audit, not selected)

The audit's LOW-severity findings were not turned into plans this round —
re-run `improve-animations` with `plan <description>` for any of these
individually, or select them next time the audit is re-run:

- Bare `transition` (=`transition-all`) on auth-form inputs, TransactionsList
  row hover, TransactionCalendar day buttons — should target
  `transition-colors`.
- Ungated `:hover` motion (missing `@media (hover: hover) and (pointer:
  fine)`) on dialog/sheet close buttons and combobox scroll buttons.
- Progress-bar fills using `transition-all` instead of `transition-[width]`
  (`loading-bar.tsx`, `Intelligence.tsx`, `Reports.tsx`, `Empresas.tsx` —
  the last also missing an explicit duration).
- No stagger on Categories/Goals card-grid entrances (all cards animate
  in simultaneously).
- Missed-opportunity teleports: NotificationBell unread badge, news-carousel
  content swap on tick/nav click, GoalDialog step 1→2 transition,
  TransferDialog insufficient-balance message, StatementImportDialog
  form→progress swap, TransactionsList bulk-select toolbar mount/unmount,
  Dashboard "Actividad Reciente" list missing the animate-in treatment
  TransactionsList uses for equivalent rows.
- Missing `active:scale-[0.97]` press feedback on several auth CTA buttons
  (Login, Register, ForgotPassword, ResetPassword), inconsistent with
  Landing's CTAs which already have it.

## How to execute a plan

Each plan file is fully self-contained — it can be handed to a fresh agent
(no context from this audit) or run through `/animate` referencing the file
path. To execute with this skill's own executor:

```
improve-animations execute plans/001-reduced-motion-overlay-gate.md
```

This dispatches an executor in an isolated worktree and reviews the diff
against the `review-animations` bar before reporting back.
